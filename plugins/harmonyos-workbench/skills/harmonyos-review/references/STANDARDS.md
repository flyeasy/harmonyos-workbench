## 1. 严重度

### BLOCKER

通常需要 E2–E4 直接证据：

- 关键入口、返回或主任务不可完成；
- Pending、缓存或定时器被呈现为真实成功；
- 页面接收错误类型或其他页面内容；
- 大字体、目标窗口或输入下核心操作不可用；
- 关键按钮无辅助工具语义或存在焦点陷阱；
- 明确 AppFreeze、崩溃、无界内存或严重长帧；
- 把 House Style 作为官方要求驱动大范围错误改造。

### MAJOR

- 生命周期重入或旧请求可能覆盖当前状态；
- 跨设备只是等比缩放；
- safe area/IME 导致明显遮挡或双重留白；
- 核心反馈缺少按下、禁用、加载或错误状态；
- 手势离手速度断层、动画锁住输入；
- 重要路径只有静态证据。

### MINOR / NOTE

用于不阻断任务的层级、Token、一致性、低频精致度问题或待验证建议。

## 2. 状态与所有权

检查：

- 每个用户可见状态的权威来源；
- 本地缓存、远端事实和视觉投影是否区分；
- 链路、服务能力、会话存续和业务操作是否正交；
- `requestId`、版本或取消策略是否阻止乱序；
- 标签/导航状态与页面内容是否分离；
- 页面是否验证 owner、route、content mode 和 capability；
- 未知类型是否失败关闭。

H4 实战反例：

- App→Relay 在线被写成电脑在线；
- session TTL 被写成远端进程仍在重试；
- 二进制内容因“不是 PDF”而默认读成文本；
- 旧页面在销毁前收到新页面正文。

## 3. 生命周期

检查冷/暖启动、页面创建、返回重入、前后台、窗口变化和覆盖安装。

资源必须成对：

| 资源 | 结束条件 |
| --- | --- |
| subscription | owner 离开/销毁 |
| interval/poll | 页面离开或后台 |
| timeout | 新触发、离开页面 |
| async request | cancel/requestId 失效 |
| dialog guard | success/error/dismiss |
| WebView bridge | 页面销毁 |

升级问题：

- 属性初始化读取尚未创建的 `@StorageProp`；
- 页面离开后轮询继续写状态；
- 旧计时器提前关闭新一轮胶囊；
- Dialog action 中列表删除与双重 reload 同帧重入；
- 覆盖安装后持久化状态破坏页面创建。

## 4. 适配与几何

检查：

- Window content rect、system avoid area、页面 padding 和局部 inset；
- 是否全屏/沉浸式；
- IME 是覆盖、平移还是重排；
- WebView/Canvas/终端的本地几何是否误映射为远端 resize；
- 宽屏是否改变导航、密度或分栏；
- 大字体、长文本、语言和 RTL；
- 鼠标、键盘、遥控器和触摸状态。

不要看到“安全区变量存在”就判正确。若 Window 已避让系统栏，页面再次加相同 padding 会形成双重空白。

## 5. 动态集合

检查：

- `ForEach` / `LazyForEach` key 表达身份；
- `@State` 集合修改是否通过可观察更新；
- count、language、selection 变化是否真正刷新；
- key 是否因塞入过多可变字段而破坏焦点和动画；
- 删除是否只触发一次数据源通知；
- 列表显示、计数和筛选来自同一模型。

## 6. 动效与手势

### 公开参考量级

- 简单颜色约 100ms；
- 很短动作约 150ms 内；
- 局部约 200ms；
- 短距离约 250ms 内；
- 复杂约 300ms；
- 长距离或全屏约 350ms 内。

这些是参考，不是统一硬阈值。

### ArkUI Gotchas

- 物理曲线实际时长不由普通 `duration` 控制；
- Navigation 默认表现可能因设备不同；
- `geometryTransition` 可能与默认转场叠加；
- 出现/消失优先 `transition`；
- 高频位置/大小变化优先图形变换；
- 同参数状态变化合并到一个 `animateTo`；
- 不用 `setTimeout` 手写逐帧；
- ArkUI 普通 drag 自动化不一定能证明长按 `onDragStart`。

### 瞬态反馈

检查：

- 重复触发是否重置可见期；
- 旧 timer 是否会关闭新状态；
- 自动化是否在控件淡出后仍点击旧坐标；
- 页面退出是否清理；
- 反馈消失是否影响业务状态。

## 7. 无障碍

检查：

- 非文本操作的名称、角色和状态；
- checked 与 selected 语义；
- 分组和焦点顺序；
- Dialog 关闭后焦点返回；
- 大字体、长文本和可滚动 Dialog；
- 颜色是否为唯一信号；
- 自绘内容的虚拟节点；
- pending、success、failure 的播报时机。

关键路径无法被辅助工具理解通常为 Blocker。

## 8. 性能

检查：

- 高频手势是否修改 `width` / `height` 触发重复布局；
- WebView、PDF、多格式切换是否出现内存不回落；
- 列表是否重复全量刷新；
- 大数据路径是否有 LazyForEach、分页或预算；
- 页面切换 PID 是否变化；
- jscrash、AppFreeze、Fatal、长帧与内存证据；
- Release 或接近发布配置是否复核。

性能工具数据与任务体验都需要；其中一个不能替代另一个。

## 9. 证据完整性

### 常见假象

- 空或部分 layout dump；
- 系统状态栏/其他应用污染；
- 测试样本变化；
- 历史标签、Dialog、输入法或最大标签数污染前置；
- HDC 错误被脚本误解析；
- 坐标来自旧布局；
- transient UI 已淡出；
- 自动化手势与真实 ArkUI 识别器不同。

诊断顺序：

1. target 与 API；
2. 前台 bundle；
3. 截图；
4. PID；
5. 日志/故障文件；
6. 测试前置；
7. 重触发后立即操作；
8. 人工或专项复核。

## 10. 通过门槛

### 不通过

存在一个证据充分的 Blocker。

### 有条件通过

无 Blocker，但存在 Major 或关键设备/输入/生命周期证据缺口。

### 通过

- 无 Blocker 和 Major；
- 主路径与失败/恢复路径有证据；
- 关键设备、窗口、输入、主题和字号已覆盖；
- 自定义数值来源清楚；
- 无障碍与性能证据足够；
- 自动化边界和未验证项明确；
- 结论对应当前构建或当前提交，而不是旧产物。
